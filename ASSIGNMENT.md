The implementation may use a small corpus, tokenizer and model. The goal is not scale. The goal is to prove that the data system is correct, reproducible, auditable and efficient.

The system must demonstrate:

- Immutable tokenized shards with manifests
- Frozen tokenizer and content hashes
- Packing policies for different data types
- Correct loss masks, attention masks and position ids
- Curriculum stages, lane weights and protected floors
- Evaluation and validation firewalls
- OPUS acceptance, rejection, deferral and protected-floor override
- Training consumption and learning ledgers
- Token-level or sample-level loss tracking
- Checkpoints tied to ledger offsets
- Crash recovery without skipped or repeated batches
- Replay of the same historical data stream
- Forking from an earlier checkpoint
- Packing utilization and useful loss-bearing tokens per second

The final run must deliberately crash, resume from the saved checkpoint and prove that the next batch is exactly the expected batch. It must also replay an earlier interval and prove that the reconstructed batch ids, token spans and hashes match the original run.

## Evaluation

The assignment carries 1,000 points.

Evaluation will happen in three steps.

### Step 1: Execute

The submitted command will be run to regenerate the complete submission_artifacts/ directory.

### Step 2: Verify Evidence

The execution log, evidence.json and evidence.md will be checked against the generated manifests, ledgers and reports.

### Step 3: Inspect Code

The code will be inspected to verify that the evidence was produced by the implementation and that the required behaviour was not simulated or hardcoded.

A subsystem receives full credit only when its result is supported by reproducible evidence.

Examples:

- If resume repeats or skips a batch, the resume section fails.
- If replay produces different batch hashes, the replay section fails.
- If evaluation data enters a loss-bearing batch, the firewall section fails.
- If reported packing or throughput numbers cannot be reconstructed, those claims will not receive credit.

> The assignment is complete only when the system can prove what it consumed, why it consumed it, what the model learned from it and how the run can be reconstructed.
